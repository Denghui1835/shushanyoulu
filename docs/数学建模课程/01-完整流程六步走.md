# 完整流程六步走（做菜式拆解）

把一次建模比赛当成**做一桌菜**：先看客人点什么（审题），再决定做什么菜（假设），列菜单（建模），开火（求解），试吃（检验），最后摆盘上桌（论文）。

## 第一步：审题 —— 把题目读成"要算什么"

- 圈出**名词**：题里的对象、数据、约束，一个都别漏。
- 分清三类信息：**已知**（题目给的）、**要求**（要你回答的）、**可假设**（题目没说但可以合理定的）。
- 用一句话复述：*"这道题要我在给定条件下，找到让 X 最大/最小的方案，并给出理由。"*
- 常见错误：急着建模，题目里的隐藏条件（比如"仅考虑工作日""成本含损耗"）没读出来，模型从一开始就跑偏。

## 第二步：假设 —— 给模型画边界

现实问题没法 100% 还原，必须简化。假设是"**我愿意放弃哪些细节，来换取模型可算**"的声明。

好假设的标准：

- **合理**：不违背题目明文要求。
- **写清楚**：每个假设都要写出来，不能藏在心里。
- **诚实**：明显会影响结果的简化，要标注并做说明。

例：规划送货路线，假设"车速恒定 40km/h""每个客户只送一次"——这就是把模型从"无限复杂"降到了"可求解"。

## 第三步：建模 —— 把话说成式子

通用骨架是：

> **目标函数（要优化什么）+ 决策变量（能改什么）+ 约束条件（不能违反什么）**

如果你不会写复杂式子，先从"变量之间的关系"写起：

- 设变量 $x$：要决策的量。
- 找关系：费用 = 单价 × 数量；满意度 = 服务时间 / 等待时间……
- 定边界：总预算 ≤ 100 万；数量 ≥ 0 且为整数。

模型不是越复杂越好。**对题、可解、可解释**，比炫技重要得多。

## 第四步：求解 —— 让工具干活

按模型类型选工具：

| 模型类型 | 常用工具 |
|---|---|
| 线性/整数规划 | Python 的 `pulp`、`scipy.optimize.linprog` |
| 预测/拟合 | `numpy.polyfit`、`sklearn` 回归 |
| 评价排序 | AHP 手算表或代码 |
| 仿真 | `numpy.random` 蒙特卡洛 |
| 图论 | `networkx` |

求解结果要**留证据**：代码、中间表、收敛情况，全进附录。

## 第五步：检验 —— 结果凭什么信

评委最烦"算出来就交"。检验三件套：

1. **对账法**：用题目给的真实数据对一对，误差在可接受范围吗？
2. **换方法**：换一种算法/工具重算，结果一致吗？
3. **敏感性**：把关键参数上下浮动 10%~20%，结论还稳吗？

如果结论对参数极敏感，说明模型脆，要么补假设，要么把"敏感区间"写进结论。

## 第六步：论文 —— 把过程讲成故事

论文是给评委看的**第一手材料**，不是作业记录。结构上记住"**先结论，再过程**"：

1. 摘要：每问一段，方法 + 关键数字 + 一句结论。
2. 问题重述与分析：证明你读懂了题。
3. 模型假设与符号说明。
4. 模型建立：一题一模型（或一个综合模型分问用）。
5. 模型求解：算法 + 结果表。
6. 检验与敏感性分析。
7. 模型评价（优点 + 不足 + 改进方向）。
8. 参考文献与附录（代码必须可运行）。
